 1. O QUE ESTÁ SENDO PEDIDO NA ETAPA 1 (AULA 06/10 - 0,25 PONTO NA AC-3)
-------------------------------------------------------------------------------
Objetivo da etapa: estabelecer as fundações de engenharia, banco de dados e
documentação do produto.

PASSO 1 - Organização do Grupo e Repositório
  - Formar grupo de 3 a 5 alunos.
  - Criar um repositório PÚBLICO no GitHub com o nome exato: PROJETO-MESAFARTAI
  - Adicionar todos os integrantes e o professor como colaboradores.

PASSO 2 - Arquivo README.md e Pasta /docs
  - README.md na raiz contendo:
      * Título oficial: "MESAFARTAI - Logística e Inteligência Assistiva no
        Combate à Fome";
      * Descrição resumida da solução e alinhamento com a ODS 2 da ONU;
      * Nome completo e RA de cada integrante.
  - Pasta /docs com:
      * docs/regras.txt (este arquivo) descrevendo o que é pedido na etapa 1;
      * docs/escopo_projeto.md com o problema de negócio, o público-alvo
        (Doadores x ONGs), o escopo das intenções e os dados coletados no chat;
      * docs/arquitetura_mesafartai.png (modelo de arquitetura em camadas);
      * docs/diag_fluxo_mesafartai.png (diagrama de fluxo de dados).

PASSO 3 - Identidade Visual e Logotipo via IA
  - Formular um prompt criativo e gerar o logotipo com uma IA generativa.
  - O logo deve unir alimento/acolhimento + tecnologia/IA assistiva.
  - Salvar em assets/logo_mesafartai.png.
  - Registrar o prompt exato utilizado em docs/escopo_projeto.md.

PASSO 4 - Script de Banco de Dados (src/database.py)
  - Script Python que inicializa o banco SQLite3 "mesafartai.db" com as
    tabelas: usuarios, doacoes e matches.
  - Popular o banco com dados de teste (seeds): 2 ONGs e 2 doadores.
  - O script deve executar sem erros e gerar o arquivo mesafartai.db.

ENVIO
  - E-mail ao professor até o final do horário de aula:
      Assunto: [MESAFARTAI] - Nome do Grupo - Turma Terça
      Corpo:   Integrantes (Nome + RGM + Curso) + link do repositório GitHub.
  - Só há validade e nota se a atividade for realizada em sala de aula.

 2. REGRAS INTERNAS DO GRUPO
-------------------------------------------------------------------------------
  R1. Toda alteração de código vai para o GitHub via commit com mensagem
      descritiva (ex.: "feat: cria tabela de matches").

  R5. Cada entrega semanal é revisada por pelo menos um outro integrante
      antes do envio ao professor.
  R6. Atividades avaliativas são realizadas em sala de aula, no horário da
      disciplina, com todos os integrantes presentes.
